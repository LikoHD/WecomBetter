# 每次打包注意事项

后续改功能、修样式、发版前，按这份做。漏掉任一步，文档页常见就是头像 / 关联文档不出现，或控制台报 `Cannot use import statement outside a module`。

## 为什么必须打包

Manifest 里声明的 content script（MAIN、ISOLATED）都是**经典脚本**，不能写 `import`。

`"type": "module"` 只对下面两类有效：

- `background.service_worker`
- 扩展页（popup）

把它写在 `content_scripts` 上会被 Chrome 忽略。企微文档 CSP 还会拦页面自己加载的 `chrome-extension://` 脚本。所以注入只能走打包后的 IIFE。

源码可以继续用 ESM 拆文件；**用户实际跑的是 `dist/` 里的产物**。

## 两份必须打出来的文件

| 源码 | 产物 | 运行环境 | 作用 |
|---|---|---|---|
| `src/page-bridge.js`（会打进 `shared.js` 里采集用到的部分） | `dist/page-bridge.iife.js` | MAIN | 读页面协作数据，派发快照 |
| `src/content.js`（会打进 `refs.js` / `viewers.js` / `search.js` / `toolbar.js` / `wander.js` / `shared.js`） | `dist/content.iife.js` | ISOLATED | 收快照、按开关画 UI |

改了上表任一源码，都要重新打包。只改 `src` 不打包就重载，页面还是旧逻辑。

## 每次改完的固定顺序

1. 在仓库根目录执行：

   ```bash
   npm run build
   ```

2. 确认这两份都更新了（时间戳、体积）：

   - `dist/page-bridge.iife.js`
   - `dist/content.iife.js`

3. 打开 `chrome://extensions`，在 WecomBetter / 企微搭子 上点「重新加载」
4. 回到企微文档页**硬刷新**（⌘⇧R / Ctrl+Shift+R）
5. 关掉油猴里的旧脚本，避免两套 UI 叠在一起

不要只刷新文档页、不重载扩展；也不要只重载扩展、不硬刷新文档。

## 哪些改动要打包

要跑 `npm run build`：

- `src/page-bridge.js`
- `src/content.js`
- `src/refs.js`
- `src/viewers.js`
- `src/search.js`
- `src/toolbar.js`
- `src/wander.js`
- `src/shared.js`（采集或 UI 任一边用到都要打）

不用打包，改完重载扩展 + 硬刷新即可：

- `src/page/styles/viewers.css`
- `src/page/styles/refs.css`
- `src/page/styles/wander.css`
- `src/page/styles/search.css`
- `src/page/styles/toolbar.css`
- `src/popup/*`
- `src/background/service-worker.js`
- `manifest.json`（改 matches、权限、版本号等）
- `icons/`

`manifest.json` 改完必须重载扩展，硬刷新文档不够。

## 禁止

- 不要给 `content_scripts` 加 `"type": "module"`
- 不要把 `src/content.js` / `src/page-bridge.js` 直接写进 `manifest.json` 的 `js`
- 不要在 MAIN 里用 `import`，也不要往页面 DOM 插 `chrome-extension://` 脚本
- 不要只改 `src` 不打包就让用户重载
- 不要用 `eval` / `new Function` 绕 CSP

## 自检

打包成功后，两份产物开头应是 `(() => {`，**不能出现顶层 `import`**。

文档页控制台：

- `window.__WECOM_BETTER__` 等于当前版本号（现在是 `"1.0.3"`）
- 没有 `Cannot use import statement outside a module`
- 顶栏能看到快捷搜索和在看头像；智能文档 / 普通文档滚到文末能看到「本文关联文档」（有引用时）和右侧 You may also wander

## 加新功能时怎么接

1. 开关默认值放 `src/shared.js`
2. 采集写进 `src/page-bridge.js` 的快照
3. 渲染写进 isolated 模块（或新文件），由 `src/content.js` 按开关调用
4. 新 isolated 文件要用 ESM `import` 进 `content.js`，**不要**再单独挂到 `content_scripts.js`
5. `npm run build`
6. 需要开关时改 `src/popup/index.html` + `popup.js`
7. 需要样式时加 CSS，并在 `manifest.json` 的 isolated `css` 数组里挂上
8. 重载扩展，硬刷新文档

MAIN 只采集、派发 `wecom-better:snapshot`；`chrome.storage` 只在 isolated / popup / service worker。

## 发版时额外看一眼

- `package.json`、`manifest.json`、popup 上的版本号是否一起改
- `README.md` 里写的 `window.__WECOM_BETTER__` 版本是否同步
- `src/page-bridge.js` 里赋值的 `window.__WECOM_BETTER__` 是否同步
- `dist/` 两份 IIFE 是否已按上述版本重新打过
